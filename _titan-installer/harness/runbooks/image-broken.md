# Runbook -- Product Image Broken / 404 in Storefront

**Symptoms:** "Product image not loading", "placeholder showing instead of image", "image works on PDP but broken on PLP".

**Severity:** P1 if site-wide. P2 if one product / one image type. P3 if intermittent.

## Step 1 -- Collect

- Product SKU
- Image type (primary / thumbnail / gallery / configurator variant)
- Page where broken (PLP / PDP / cart / search)
- Customer geography (CDN edge varies)
- Direct image URL if visible in DevTools

## Step 2 -- Identify the image pipeline

Image flow:
1. Asset uploaded / managed in AEM Assets (DAM)
2. Asset renditions generated by AEM
3. DAM URL referenced by storefront via AEM Sites + GraphQL
4. CDN edge caches the rendition

| Layer | Where | Look for |
|---|---|---|
| 1. DAM original | AEM Assets UI (web console) | Original asset present, metadata correct |
| 2. AEM rendition | AEM Sites -> asset detail -> Renditions tab | Required size variants generated |
| 3. AEM dispatcher | `/var/log/dispatcher/` | Asset URL cached / served |
| 4. CDN edge | CDN provider console | Edge HIT / MISS, stale response |
| 5. Storefront network panel | Browser DevTools | Image URL, HTTP status (404 / 403 / 200) |
| 6. CIF GraphQL response | Adobe I/O activation logs | Product query returns correct image URL |

## Step 3 -- Common causes (ranked by frequency)

| # | Cause | How to confirm | Recommended action |
|---|---|---|---|
| 1 | DAM asset missing / deleted | AEM Assets shows no asset for the SKU | ESCALATE TO PIM team / Brand team: re-upload asset |
| 2 | Rendition not generated for required size | DAM has original, no size variant present | ESCALATE TO the AEM owner: trigger AEM rendition workflow |
| 3 | CDN edge cached a 404 (negative cache) | DevTools: image URL returns 404, CDN cache HIT | ESCALATE TO the AEM owner + CDN admin: purge negative cache |
| 4 | Asset path changed but storefront URL stale | GraphQL returns old DAM path | ESCALATE TO the architecture owner + the commerce owner: PIM-to-AEM asset reference sync |
| 5 | Permissions on DAM asset (denied to anonymous) | DevTools: 403 not 404 | ESCALATE TO the AEM owner: asset ACL check |
| 6 | Wrong image variant referenced (PLP needs thumbnail, got original) | GraphQL response field mismatch | ESCALATE TO the architecture owner (frontend) + the commerce owner (CIF resolver) |
| 7 | Localised asset missing for market | EN has asset, DE missing | ESCALATE TO Brand team + Localisation: asset localisation |
| 8 | Lazy-load library failed silently | DevTools: image element never got `src` populated | ESCALATE TO the architecture owner (frontend): lazy-load fallback |

## Hard stop reminders

- DAM assets may contain copyright metadata or brand-sensitive originals -- do not download or display in tickets
- CDN cache purge is a the AEM owner action -- production support never invalidates cache directly
- Wrong asset reference in PIM is a PIM data correction (PIM team), not an asset issue
- Negative cache (404 cached) is the most common "but the image is in DAM!" cause -- always check CDN cache age before deeper investigation
